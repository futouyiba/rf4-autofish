# RF4 自动钓鱼 · 使用指南

适用于 `RF4AutoFish v1.0.0`（Windows 64 位）。

拿到手只有一个文件，双击就能钓：**不需要装 Python、不需要装依赖、不用懂命令行**。

> **面板和后台是两个进程。** 面板只是遥控器，真正抛竿/搏鱼的后台在关掉面板后
> 仍会继续。要停钓鱼请点「立即停止」或「紧急停止」。

---

## 0. 先说清楚能做什么、不能做什么

| | 说明 |
|---|---|
| ✅ 能做 | 自动抛竿、等咬钩、提竿、搏鱼时自动调摩擦片、入护、重新抛竿，循环到你停 |
| ✅ 需要 | Windows 10/11 x64；游戏能正常进世界；画面 **16:9**（按 1920×1080 标定） |
| ❌ 不支持 | 自动补饵 / 自动换钩 / 自动换钓点 / 自动修理 —— 饵没了、线断了得你自己处理 |
| ❌ 不包含 | 游戏本体、账号、任何外挂式注入；它只是替你按键 |
| ⚠️ 效果 | **白天稳定**；夜里鱼图标看不清时可能漏口，详见 [第 7 节](#7-什么时候效果会变差) |

---

## 1. 开始前，先做三个检查

1. 游戏已进世界，人物**站在水边**，屏幕底部出现「钓具准备好，可以抛掷一下」。
2. 游戏窗口标题是 `Russian Fishing 4`（改过标题的启动器会识别不到）。
3. 画面比例 16:9（1920×1080 最稳；全屏/窗口化都行）。

三条不满足，后台启动后也会停在 `PROBING` 不抛竿。

---

## 2. 第一次开钓（三次点击）

1. **双击 `RF4AutoFish.exe`**（单文件版首次启动会解包，等 5~15 秒）。
   面板会自动贴到游戏窗口右侧。
2. 点 **「启动后台（离线时）」** → 状态从 `离线` 变成 `PROBING`。
3. 点 **「开始/恢复自动」** → 模式从 `OBSERVE` 变成 `AUTO`，开始抛竿。

> **为什么第一次要点两下？** 后台起来默认是 `OBSERVE`（只看不动手），
> 必须显式授权才会接管键鼠。这是防呆设计，不是卡住了。

跑起来之后你应该看到状态这样循环：

```
CALIBRATING → CASTING → WAIT_BITE → FIGHT → LAND → SETTLE → CALIBRATING …
```

`kept` 每加 1，就是一条鱼进水护。

## 3. 面板怎么看

| 行 | 含义 |
|---|---|
| **状态** | 当前在干什么，见下方状态表 |
| **模式** | `OBSERVE` 只看不动 / `AUTO` 自动操作 / `BLOCKED` 被前置条件挡住 |
| **原因** | 进入该状态的理由（诊断用，例如 `protocol_fight` = 协议判定中鱼） |
| **cur / 可信度** | 摩擦片档位（1~29，越大越紧）/ 该读数的可信度 |
| **bar / tier** | 力度条等级 / 色带档（1 绿 2 橙 3 红） |
| **ring** | 线杯圆环读数；`unknown` 表示这一刻读不到（夜间常见，正常） |
| **desired / emitted** | 期望按的键 / 实际发出的键（怀疑卡键时看这里） |
| **kept** | 本次运行入护的鱼数（重启后台会清零，游戏里的鱼护数不受影响） |
| **NET待确认 / 心跳** | 是否需要人工确认抄网 / 后台心跳年龄（>2 秒 = 后台卡住或已退出） |
| **回执** | 上一次按钮操作的结果 |

状态行颜色：绿 = 在线且在跑，黄 = 有告警，红 = 离线或故障。

## 4. 按钮与热键

按钮上写的是裸键名，实际热键都是 `Ctrl+Alt+Shift+Fn`（单独按 F6 不会触发，
不会和游戏里的抬竿键打架）。

| 按钮 | 热键 | 作用 |
|---|---|---|
| 启动后台（离线时） | `Ctrl+Alt+Shift+F6` | 拉起后台进程 |
| 开始/恢复自动 | `Ctrl+Alt+Shift+F7` | 授权自动接管（OBSERVE → AUTO） |
| 仅观察 | `Ctrl+Alt+Shift+F8` | 收回授权，只观察不动键 |
| 立即停止 | `Ctrl+Alt+Shift+F10` | 立刻停，不等当前这条鱼 |
| 本条结束后停 | `Ctrl+Alt+Shift+F9` | 打完当前这条再停，不会断线丢鱼 |
| 确认钓具就绪 | — | 误判"没准备好"时人工放行一次 |
| 我已手动收网 | — | 抄网卡住、你手动收完后点一下 |
| 紧急停止 | — | 确认后强杀后台并松开所有按键（鼠标失控时用） |

## 5. 状态对照：正常 / 卡住怎么办

| 状态 | 正常表现 | 卡住时的处理 |
|---|---|---|
| `PROBING` | 1~3 秒内转 `CALIBRATING` | 超过 20 秒不抛：检查第 1 节三条（尤其「钓具准备好」是否出现） |
| `CALIBRATING` | 1~2 秒 | 反复来回：游戏窗口不在前台 |
| `CASTING` | 2~5 秒进 `WAIT_BITE` | 一直不出去：看日志是否 `cast_failed` |
| `WAIT_BITE` | 30~90 秒上鱼；超时自动收线重抛 | 长时间没鱼：可能没饵、钓点没鱼、或夜里漏口 |
| `FIGHT` | 20 秒~4 分钟 | **超过 4 分钟会自动放弃**（判为挂底，收线重抛），见第 7 节 |
| `LAND` → `SETTLE` | 1~3 秒，`kept +1` | 停在 `LAND` 不动且 `NET待确认`：手动抄网后点「我已手动收网」 |
| `FAULT` | 不应该出现 | 点「立即停止」→「启动后台」，仍不行就重启游戏和面板 |

## 6. 常见问题

**状态一直是「离线（endpoint unavailable）」**
后台没起来。点「启动后台（离线时）」；若回执报错，看日志最后几行（第 8 节）。

**回执说"已请求启动"但还是离线**
后台启动后立刻退出了。常见原因：游戏没开 / 窗口标题不对 / 不是 16:9 /
单文件版被杀软拦了（加白名单）。

**面板挡住了游戏，或跑到屏幕外**
拖标题栏挪回来；或取消勾选「跟随游戏」自己摆位置。

**关掉面板，鱼还在钓？**
正常。面板是遥控器，后台是实体。

**换一台电脑 / 换分辨率**
单文件版：把 exe 拷过去就行。onedir 版：整个目录一起拷。
**非 1920×1080 需要重新标定**，当前版本按 1920×1080 硬编码。

**杀毒软件报毒**
PyInstaller 打包的程序常见误报，加信任即可；单文件版误报概率更高（自解包行为）。

**单文件版启动很慢**
正常：每次启动要把约 204 MB 解包到 `%TEMP%`，冷启动 5~15 秒。

**%TEMP% 里留下 `_MEIxxxx` 目录**
强杀进程导致的残留（正常退出会自己清），手动删掉即可。

## 7. 什么时候效果会变差

| 情况 | 表现 | 怎么办 |
|---|---|---|
| **夜里/逆光** | 鱼图标几乎看不见，可能一直等不到咬钩 | 装一次 Npcap 并按 [第 10 节](#10-进阶接入协议层夜间更稳) 开启协议层，夜间照样稳 |
| **钩子挂草/挂底** | 一直 `FIGHT` 拉不上来 | 超过 4 分钟会自动收线重抛；反复挂草就换个朝向或钓点 |
| **饵没了** | 抛出去长时间零咬钩 | 需要你手动补饵（本版不支持自动补饵） |
| **线/钩断了** | 状态一直 `PROBING`、底部没有「钓具准备好」 | 进游戏重新装钓组 |
| **鱼护满** | 钓上来放不进 | 去卖掉或换鱼护 |
| **服务器掉线** | 画面冻结、按键无响应、日志不再更新 | 重启游戏，重新登录，再启动后台 |

## 8. 文件、日志与隐私

exe 只读自己目录，运行时文件全部写到 `%LOCALAPPDATA%\RF4AutoFish\`：

| 文件 | 内容 |
|---|---|
| `_bridge.log` | 主日志（状态迁移、每次抛竿/收线） |
| `autofish.endpoint.json` | 面板与后台的本地通信端点（**含 token，别外传**） |
| `run.pid` / `autofish.process.json` | 后台进程身份，停止时用 |
| `selftest.txt` | `--selftest` 的自检结果 |

看日志：`Win+R` → 输入 `%LOCALAPPDATA%\RF4AutoFish` → 回车。

**隐私**：程序不联网、不上传任何数据（协议层除外，那只是本地抓包）。

## 9. 进阶：命令行

同一个 exe 可以切角色，方便写脚本或放计划任务：

```bat
RF4AutoFish.exe --version          :: 版本号
RF4AutoFish.exe --selftest         :: 自检（依赖/资源/路径），结果写 selftest.txt
RF4AutoFish.exe --ctl status       :: 后台是否在跑
RF4AutoFish.exe --ctl start        :: 启动后台
RF4AutoFish.exe --ctl stop         :: 停止后台
RF4AutoFish.exe --ctl emergency-stop :: 强杀并松键
```

## 10. 可选增强：协议层（夜间更稳）

**基础模式（默认，零依赖）**：纯视觉判断，开箱即钓，白天稳定。

**协议模式（可选增强）**：读服务器消息判断咬钩/中鱼，夜间/逆光也稳。
抓包器已经打进 exe，唯一的外部依赖是 **Npcap 驱动**（许可证不允许随包
分发，装一次即可）。全程在面板上操作，不用命令行：

1. 看面板底部「协议层：…」状态行。
   - `未安装 Npcap · 纯视觉（夜间弱）` → 点 **「安装指引(Npcap)」**，
     浏览器会打开官网，下载安装（勾选 *WinPcap API 兼容*）。
   - `未运行 · 纯视觉（夜间弱）` → Npcap 已装，进入第 2 步。
2. 点 **「启动协议层」**（会弹一次 UAC 提权，这是嗅探的硬要求）。
   状态行变成 `运行中 (pid=xxx) · 夜间也稳` 即成功。
3. **顺序铁律：先点启动协议层、再让游戏登录**（握手包只有一次，顺序
   反了这条连接就解不开；重登一次游戏即可恢复）。

也可以用命令行等价操作（写脚本用）：

```bat
RF4AutoFish.exe --sniff-ctl start    :: 等价于面板「启动协议层」
RF4AutoFish.exe --sniff-ctl status   :: 看驱动/进程状态
RF4AutoFish.exe --sniff-ctl stop     :: 停止抓包
```

其他动作：

```bat
RF4AutoFish.exe --sniff-ctl status   :: npcap 装没装、抓包进程在不在
RF4AutoFish.exe --sniff-ctl stop     :: 停止抓包
```

抓包器把状态写到 `%LOCALAPPDATA%\RF4AutoFish\_sniff\state.json`，
主程序会自动找到。接上后面板「原因」列会出现 `protocol_fight`、
`protocol_line_in_water` —— 说明判据升级成了"视觉 + 协议"双确认。

| 有协议层 | 没有协议层 |
|---|---|
| 咬钩/中鱼由服务器消息确认，夜间照样钓 | 只看鱼图标，夜里可能漏口、卡在等口 |
| 收线/入护有协议否决，不会假收线 | 圆环读数有歧义时可能空拉 |

## 11. 进阶：OCR（自己的环境）

只有「读地图坐标自动走回钓位」「读鱼护数量」用得到，普通钓鱼**不需要**。

把项目里的 `venv-ocr` 目录（约 360 MB）放到 exe 同级即可；没有也不报错，
只是这些读数返回空。

## 12. 从源码自己打包（开发者）

```bash
cd bot
bash build_exe.sh            # onedir + zip（日常用）
bash build_exe.sh --onefile  # 单文件 exe（分发用）
```

两种产物的取舍（同一个 spec，靠 `RF4_ONEFILE=1` 切换）：

| | onedir（zip） | onefile（单 exe） |
|---|---|---|
| 分发形态 | exe + `_internal/` 整个目录 | 一个 94 MB 文件 |
| 冷启动 | 快 | 慢 5~15 秒（解包到 `%TEMP%`） |
| 临时空间 | 无 | 每进程约 204 MB，退出自动清 |
| 面板+后台 | 共用一份依赖 | 各解一份，合计约 400 MB |
| 杀软误报 | 中 | 偏高 |

## 13. 边界与免责

* 仅供**本地私服/单机**学习用途，不含游戏本体与账号信息。
* 运行期间会接管真实键鼠（F5/F6/左右键/滚轮），请保持游戏窗口在前台，
  **不要同时手动操作**。
* 拿不准就按「紧急停止」：它优先松键，其次才杀进程。
