# 小退重登（S10_RELOGIN）

面向"线快被鱼拉光"这一种场景：**线杯剩线 < 15% 时主动退出重进**，把这条鱼和
这套线组一起放弃，换一条干净的会话继续钓。不做定时休息。

## 1. 为什么是 15%，为什么直接退

圆环（`wheel.png` 外圈）读的是**线杯上还剩多少线**，刚抛出去约 0.93。大鱼持续
出线会一路往下掉，掉到很低时继续拉只有两个结局：断线，或者线被拉空后彻底卡住。
玩家（2026-11-06）的判断是：**到这个程度不如直接小退重进**，代价只是一条鱼。

所以触发判据是"结果导向"的，不是"还差多少米"：

| 条件 | 值 |
|---|---|
| 触发阈值 | `ring_ratio < 0.15` |
| 连续确认帧 | 2 帧（约 0.4 秒） |
| 覆盖状态 | `FIGHT` / `LAND` / `NET`（三者共用 `_tick_fight`） |
| 不触发 | `ring_ratio is None`（图标没画/被挡）、负值、非有限值 |

**"没测到"绝不能当成"没线了"**：`None` 直接清零计数，不累计、不动作。单帧
低读数也会被下一帧的正常读数打断，不会因为一次误读就退游戏。

## 2. 流程与判据

```
FIGHT/LAND/NET ──ring<0.15 连续2帧──▶ S10_RELOGIN
                                        │ 停子机、松 F5/F6（_enter 自动做）
                                        ▼
   Esc ─▶ 点「退出」 ─▶ 点「是」 ─▶ 等登录界面 ─▶ 点「登录」 ─▶ 等世界
                                        │
                                        ├─ 成功 ─▶ CALIBRATING（重新校准 17）─▶ CASTING
                                        └─ 失败 ─▶ FAULT（停机交还人工）
```

全程**不用 OCR**。每一步只回答"现在在哪个界面"，用亮度结构判据就够：

| 状态 | 判据（1920×1080 客户区） |
|---|---|
| `world` | 整屏灰度均值 > 90（场景是亮的） |
| `dark` | 均值 < 48（加载中 / 菜单压暗） |
| `login` | 均值 ∈ [60, 80] **且** 登录按钮带（y 695–750、x 820–1090）亮像素占比 ∈ [2%, 12%] |
| `error` | 其余 |

判据顺序是先 `world` 再 `dark` 最后 `login`：世界里的 UI 也会把"登录按钮带"
点亮，所以必须先排除世界；而水下鱼群会出现"均值≈49、亮块≈30%"的画面，所以
登录判据必须**卡区间**，不能只看单一指标。

坐标（1920×1080 客户区，实测自 `rf4-client-ops`）：

| 元素 | 坐标 |
|---|---|
| ESC 主菜单「退出」 | (1418, 743) |
| 「确定要退出游戏吗」的「是」 | (858, 565) |
| 登录界面「登录」 | (956, 723) |

窗口不是 1080p 时按客户区尺寸等比缩放。

## 3. 失败与重试边界

| 情况 | 处理 |
|---|---|
| 点了退出但画面没变 | 重开菜单再来一次，最多 `exit_retries=1` 次 |
| 点了登录还在登录界面 | 补点，最多 `login_retries=2` 次 |
| 等登录界面超时 | 75 秒 → `ReloginError("login_timeout")` → FAULT |
| 等世界超时 | 150 秒 → `ReloginError("world_timeout")` → FAULT |
| 总超时 | 240 秒硬上限，超出立即失败 |
| 用户按停止 | `control.checkpoint()` 抛 `AutoStop`，整条流程立刻中断并松键 |
| 回调缺失 | `relogin_missing` → FAULT（绝不"假装退了"） |

**任何失败都不自动重试到无限**，也不在 FAULT 里偷偷再退一次——这是"不确定时
不作恶"的同一条原则。

## 4. 回来之后必须重置的东西

重登等于换了会话，下面这些全部作废：

- 本条鱼的 `fish_id`、搏鱼/抛竿计时（`_clear_fish()`）
- 摩擦档位账本 `_friction_cache`（`calibrated=False`）→ 必须重新做"滚到顶再回 17"
- 抄网状态假设 → `NetState.UNKNOWN`（不知道网在不在手上）
- 结算抑制标志 → 允许下一条鱼正常入护

所以成功后进入的是 `CALIBRATING`（`fight=False`，抛竿前绝对校准），**不是**
`CASTING` 或 `WAIT_BITE`。绝对校准会先滚到 30 顶格再退回 17，不依赖任何档位
记忆，重登前后档位不一致也不会错。

## 6. 还没实机验收的部分

离线测试全部通过，**不等于实机可用**。以下三条必须实机确认：

1. 按 Esc 后点 (1418,743) 是否真的弹出退出确认框（Shift 修饰是否必需）；
2. 点「是」到登录界面出现的真实耗时（决定 `login_timeout` 是否需要放宽）；
3. 重登后是否回到同一个岸边位置、装备是否保留（影响下一竿是否需要人工干预）。

第一条如果不成立，改 `ReloginConfig.shift_exit=False` 或直接改坐标常量即可，
不需要改流程。
